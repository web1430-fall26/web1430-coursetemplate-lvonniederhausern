What organization or product did you design for, and what drove your color and typography choices?

I designed a website to sell a product that was painted rocks. The rocks can be used as paperweights to add decoration and a bit of fun to people's desks. My colors were based on which ones passed accessibility requirements, and I was looking for colors that stood out and had a bit of whimsy to them.  That stood out and had a bit of whimsy to it. My topography was chosen because I liked the way. The font seems very thin, and it reminds me of my own handwriting. I figured that for a site that sells crafts. It would be a good idea to make it feel more crafted. 

How did you decide what counts as a "component" vs. a one-off element?

If an element occurred more than twice. I tended to make it a component. Because it speeds up the programming process and makes the code easier to read and implement. If an element only occurred once or twice, I just left it as a one-off since it only serves one specific purpose.

What was the hardest interactive pattern to implement accessibly and what did you learn?

The hardest interactive pattern to implement accessibility for would probably have been the product cards.  Because I am not very good at implementing images, and I had to make sure that you could visibly see all the data, and it could also be read to you if you had a screen reader. Plus, getting the little checkbox in the product cards to work took a ton of effort.

What would a developer need to know to use your style guide on a real project?

I feel like if a developer were to use my style guide on a real project, they would have to know that it is made for a shopping website. And that the color names in my CSS aren't always the most descriptive or accurate. For example, color nav, which I use for the navigation hover. I also use it in many other places on the site because I like the way the teal looks.
